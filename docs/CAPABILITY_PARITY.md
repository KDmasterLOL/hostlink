# HostLink rewrite тАФ externally observable capability parity

Source audit: 2026-10-25. Old HostLink `dev@5a1f80b`, new SSH-only rewrite `e9140457f39324ceabdc893adee0a4cf03bff93c`. This is a behavioral inventory, **not** an instruction to resurrect the retired Agent JSONL/RPC, managed Toolkit release, external OpenSSH or attestations. The final replacement MUST include a separate managed Hub for registry/invitation/revocation, plus a pinned `russh` Client and an unprivileged `russh` Agent. Static SSH host configuration is **not** the same as Hub enrollment.

## Explicit acceptance gaps and ownership

1. **Mandatory managed fleet (1C-1019/1020/1021):** Build the Hub registry/invite/enrollment/revoke owner, thin managed Client API and fresh user-scoped Agent bootstrap. New managed host check/exec/run must resolve canonical HostSpecs from Hub. Offline preflight alone does not supply this.
2. **Cancellation native acceptance (1C-1015):** The existing `hostlink-jobs` now supports authenticated `cancel` and typed `HostConnection::job_cancel` and CLI `hostlink jobs cancel`; Linux reconnect, wrong-key, descendant teardown and idempotent terminal state are covered in `crates/client/tests/agent_jobs_interop.rs`. Windows Job Object cancellation and failure/teardown states still require native checks at the same source revision. Do not conflate a requested cancellation with a terminated process.
2. **Source-exact Windows/native:** current rewrite Windows11 durable reconnect, Win7 x64/x86 and safe update/handoff need same-artifact receipts (1C-1003/1004/1008/1011). Old `dev` Win7 evidence cannot be transferred.
3. **Gateway and real host cutover:** reverse port forwarding pinned across both identities, loss/restart and fallback (1C-1009); offline old config inventory and separate owner-scoped sidecar (1C-1010) before any managed replacement.
4. **Operator TCP-forward parity:** decide and implement a bounded loopback-only CLI forward on top of existing `HostConnection::open_forward` if interactive forwarding/RDP is part of required workflows. No service proxy, auto-routing Hub, or broad network access beyond an explicitly approved destination.
5. **Artifact lifecycle:** verify terminal owned cleanup and protected SFTP/Seal retention limits. Never remove an artifact with uncertain or foreign ownership.

The old command catalog is from `origin/dev:crates/onec-access/src/cli/commands/mod.rs`; new APIs were read from `crates/client/src/{main,lib,forward,run,sftp}.rs` and `crates/agent/src/{ssh,jobs,update}.rs`.
